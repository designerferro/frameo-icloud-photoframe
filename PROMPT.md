# Prompt para recriar e manter o APK

Autor técnico do código e do APK: **Codex**. Conta de publicação/manutenção: **designerferro**.

Este texto permite pedir a recriação funcional do projeto. Para refazer esta versão a partir do código existente, seguir o README e as instruções de compilação; um modelo não garante gerar código ou binários idênticos apenas a partir do prompt.

## Pedido de implementação

Cria uma aplicação Android Java nativa, leve, chamada Photoframe, package `pt.photoframe`, compatível com Android 6/API 23 e sem Google Play Services, AndroidX ou WebView. O alvo inicial é uma Apveelveer AVE-107 Rockchip RK312x, cerca de 1 GB RAM e 1280×800, mas deve funcionar com fotografias e ecrã em orientação horizontal ou vertical.

O APK público deve ser genérico: nunca incluir um álbum pessoal, fotografias de exemplo pessoais, palavras-passe Apple, tokens GitHub ou chaves de assinatura. Pedir no próprio ecrã a ligação Site público de um Álbum partilhado iCloud (`https://www.icloud.com/sharedalbum/#TOKEN`). Guardar a configuração em SharedPreferences privados e validar esquema, host, caminho e formato do token. Explicar que quem possuir essa ligação pode ver as fotografias.

Sincronizar diretamente com os endpoints utilizados pelo site público iCloud (`webstream` e `webasseturls`), sem login Apple. Derivar a partição do token base62 conforme o site Apple. Estes endpoints não são uma API pública garantida: tratar falhas e manter cópia local. Só fotografias; não reproduzir vídeo. Ajustar JPEG a até 1280×1280, respeitar todas as orientações EXIF e guardar no espaço privado da aplicação. Publicar o novo manifesto de cache apenas após descarregar todas as imagens necessárias; em falha ou álbum vazio conservar o último conjunto. Sincronizar ao abrir e a cada 15 minutos em primeiro plano; repetir em 1 minuto se falhar. Não pedir permissão para armazenamento partilhado.

Mostrar fotografias a cada 15 segundos; toque avança. Remover barras pretas tanto na horizontal como na vertical: por defeito, foto completa sobre fundo suave e escurecido derivado da própria foto, com opção adicional CENTER_CROP para preencher recortando margens sem distorcer o primeiro plano. Manter o ecrã ligado. Dar opções de orientação automática/fullSensor, horizontal e vertical, persistidas. Toque prolongado ou botão Back abre um menu em português com estado, atualização das fotos, configuração do álbum, apresentação, definições Android e atualização do APK.

Implementar atualizações usando a última release estável de `designerferro/frameo-icloud-photoframe`. Mostrar no mesmo menu versão instalada e última release consultada. Comparar `versionCode`, não cadeias de versão; não permitir downgrade. Verificar automaticamente ao abrir, respeitando intervalo de 6 horas, e periodicamente enquanto a aplicação estiver em primeiro plano. Permitir desativar a atualização automática. A ação manual ignora o intervalo e permite forçar reinstalação da mesma release após confirmação.

Cada release contém `Photoframe-vX.Y.Z.apk`, `update.json` com versionName/versionCode/repository/author/apk/sha256/minSdk e `SHA256SUMS`. Validar repositório, release estável, tag, nome de asset, HTTPS, limites de tamanho, digest SHA-256, package name, versão interna e assinatura igual à aplicação instalada. Nunca desativar validação TLS nem usar credenciais GitHub na aplicação. Não instalar APK com assinatura diferente ou versão inferior. Usar `su -c` e `pm install -r` se existir root; caso contrário partilhar apenas o APK verificado com o instalador Android através de ContentProvider privado com concessão temporária de leitura. Não conceder acesso a outras pastas. Retomar a apresentação após MY_PACKAGE_REPLACED. Suportar BOOT_COMPLETED e o papel de HOME no Android 6.

Preparar fonte para GitHub na conta designerferro, com autoria técnica atribuída a Codex e este prompt incluído. Não criar nem publicar `.gitignore`. Todas as ferramentas, ficheiros de compilação e chaves devem ficar fora da árvore do código. Fornecer scripts Python 3 portáveis para preparar o SDK e compilar com JDK 17, Android platform 23 e build-tools 34.0.0. Usar aapt/javac/D8/zipalign/apksigner; tratar os executáveis e separadores de caminho de Windows, GNU/Linux e macOS. Verificar assinatura e gerar metadados/checksum da release. Nunca publicar a chave privada.

O README deve explicar instalação do APK e recuperação reversível do Frameo, requisitos e preparação em Windows, distribuições GNU/Linux baseadas em Debian e macOS, via auxiliar e manualmente, incluindo a compilação manual. Documentar chaves locais versus chave das releases e o facto de uma compilação assinada por outra chave não aceitar atualizações oficiais por cima. Incluir instruções de publicação de releases sem chaves nem dados pessoais. Incluir verificações de rejeição de downgrade, reinstalação automática indevida e metadados inválidos.

Preparar também um artigo em português europeu para o Pouparmelhor, com ligações para o repositório e Releases, passos práticos e sem informação sobre testes. Distinguir a instalação de um APK já disponível da compilação opcional. Não sugerir flash de uma ROM apenas por partilhar o SoC. Não assumir um método universal para obter ADB/root.
